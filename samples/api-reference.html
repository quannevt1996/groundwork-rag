Wayline API Reference

The Wayline API is organised around REST. It accepts JSON request bodies, returns JSON responses and uses standard HTTP status codes. All requests go to https://api.wayline.example/v2.

Authentication

Authenticate every request with an API key in the Authorization header: Authorization: Bearer wl_live_.... Live keys start with wl_live_ and test keys start with wl_test_. Keep keys on your server; never ship them in a mobile app or a web page.

You can rotate an API key from the dashboard at any time. When you rotate a key you choose a grace period between zero and seven days, during which the old key keeps working so you can roll out the new one without downtime.

Rate limits

Each API key may make 600 requests per minute, with short bursts of up to 100 requests allowed. Requests above the limit are rejected with HTTP status 429 and the error code WL-4291. The Retry-After response header tells you how many seconds to wait before trying again.

If you regularly hit the limit, batch several events into one call with POST /v2/events/batch before asking for a higher limit.

Idempotent requests

Network failures make it unclear whether a request was received. Send an Idempotency-Key header with any POST request and you can safely retry it: Wayline remembers each key for 24 hours and returns the original response for repeated requests instead of publishing the event twice.

Pagination

List endpoints are cursor-based. Pass limit (at most 100, default 20) and starting_after with the ID of the last object from the previous page. The response field has_more tells you whether another page exists.

Endpoints

Publish an event

POST /v2/events publishes one event. The body has a type, such as invoice.paid, and a data object. Event payloads may be at most 256 KB.

Manage endpoints

GET /v2/endpoints lists your webhook endpoints and POST /v2/endpoints creates one. An endpoint has a URL, the list of event types it subscribes to and a signing secret.

Inspect deliveries

GET /v2/deliveries/{id} returns one delivery with every attempt, including the status code and response time of each. POST /v2/deliveries/{id}/retry sends a delivery again immediately.

Errors

Errors return a JSON body with a stable code and a human-readable message. Branch on the code, never on the message text.

  • WL-4001: The request body is not valid JSON or is missing a required field.
  • WL-4011: The API key is missing, malformed or revoked.
  • WL-4031: The API key is valid but lacks the scope this request needs.
  • WL-4130: The event payload is larger than 256 KB.
  • WL-4291: Rate limit exceeded. Wait for the number of seconds in Retry-After.
  • WL-5030: Wayline is temporarily unavailable. Retry with exponential backoff.
